API Endpoints

The Timagotchi Configuration Portal provides the following REST API endpoints:

POST /api/generate-code

Generate a new 5-digit pairing code for device configuration.

Response:

{
  "code": "12345",
  "expires_in": 3600
}
GET /api/validate-code/<code>

Check if a pairing code is valid and available.

Response:

{
  "valid": true,
  "time_remaining": 3240
}
POST /api/config/<code>

Submit configuration data for a specific pairing code.

Request Body:

{
  "schedule": {
    "school_start": "09:05",
    "school_end": "15:55",
    "num_periods": 6,
    "period_length": 51,
    "passing_time": 4
  },
  "system": {
    "timezone": "America/New_York",
    "wifi_networks": [["SSID", "password"]]
  },
  "canvas": {
    "enabled": true,
    "base_url": "https://school.instructure.com",
    "api_token": "token"
  },
  "customization": {
    "theme": "dark"
  }
}
GET /api/config/<code>

Pi polls this endpoint to retrieve configuration when ready.

Responses:

  • 202 Accepted - Configuration pending (not submitted yet)
  • 200 OK - Configuration ready (returns config files)
  • 404 Not Found - Invalid or expired code
GET /health

Health check endpoint for monitoring deployment status.

Response:

{
  "status": "healthy",
  "active_codes": 3,
  "timestamp": "2025-12-15T10:30:00"
}

Configuration Schema

Complete reference for the configuration JSON structure:

Schedule Configuration

Field Type Description
school_start string School start time (HH:MM format)
school_end string School end time (HH:MM format)
num_periods integer Number of class periods (4-8)
period_length integer Length of each period in minutes
passing_time integer Time between periods in minutes
has_advisory boolean Whether school has advisory period
has_lunch boolean Whether school has separate lunch period
use_ab_day boolean Whether school uses A/B day scheduling

System Configuration

Field Type Description
timezone string IANA timezone (e.g., "America/New_York")
time_sync_mode string "disabled", "on_boot", or "periodic"
use_24_hour boolean Use 24-hour time format
wifi_networks array Array of [SSID, password] tuples

Security

The configuration portal uses a simple security model suitable for home/school use:

  • 5-digit numeric codes: 100,000 possible combinations
  • 1-hour expiration: Codes automatically expire after 60 minutes
  • One-time use: Codes are deleted after successful retrieval
  • In-memory storage: No persistent database; cleared on restart
  • HTTPS required: Always deploy with SSL/TLS enabled

Deployment

The backend can be deployed to any cloud platform that supports Python/Flask:

  • Render: Free tier available, automatic SSL
  • Railway: Simple deployment, built-in SSL
  • Heroku: Classic PaaS, requires paid dyno for 24/7
  • Self-hosted: Any VPS with Python 3.9+

See the Build Guide for detailed deployment instructions.
